# Инструкции для работы с IMU_sw

## Начало работы

1. Прочитай `docs/PROJECT_CONTEXT.md` — там состояние проекта, решения
   пользователя, планы калибровки и следующий этап.
2. По теме задачи прочитай `docs/imu_safety.md` и `docs/flash_layout.md`.
3. Проверь текущие исходники и `git status`. Контекст — снимок состояния,
   а не замена коду. При расхождении выясни причину; актуальные указания
   пользователя имеют приоритет.

Общайся с пользователем по-русски. Объясняй, что изменено, зачем, что
проверено программно и что ещё не проверено на плате.

## Правила проекта

- Не перезаписывай посторонние изменения пользователя и не выполняй
  коммиты/прошивку платы без соответствующего запроса.
- Сохраняй пользовательский код внутри USER CODE-блоков CubeMX там, где
  это применимо. Пользовательские модули подключай из верхнего CMakeLists.txt.
- Изменение бинарного протокола сопровождай обновлением описания длины,
  смещений, версии при несовместимости и тестов CRC/сериализации.
  Значения существующих enum не перенумеровывать; enum на линии кодируется
  полем фиксированного размера, а не машинным размером C enum.
- Коэффициенты калибровки и обработку отказов веди отдельно для каждого IMU.
  Коррекцию применяй до Madgwick и объединения датчиков.
- Под калибровку зарезервирован ОДИН сектор 2: 16 КиБ по адресу
  0x08008000–0x0800BFFF. Двухсекторная схема из старого обсуждения отменена
  пользователем. Не возвращай её без нового указания.
- Область калибровки не должна попадать в загружаемый образ прошивки.
  После изменений линкера запускай `tests/check_flash_layout.py` на ELF.
- Различай реализованные функции и проект интерфейса из контекста.
  Команды калибровки 0x09–0x0B пока только предложены, Flash-драйвера нет.

## Проверки

Команды сборки и ограничения окружения перечислены в PROJECT_CONTEXT.md.
Для изменений алгоритмов/протокола запускай релевантные хост-тесты.
Успешные сборки и моки не считаются проверкой реальной платы.

## Обновление переносимого контекста

После существенных изменений или новых решений пользователя обновляй
`docs/PROJECT_CONTEXT.md` и профильную документацию. Явно отмечай, что
реализовано, что согласовано, что только предложено и что осталось проверить.
Не сохраняй сюда ключи, учётные данные и содержимое личных настроек.
Эти файлы переносят инженерный контекст, а не полную историю чата.
