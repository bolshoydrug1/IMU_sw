# Устойчивость обработки IMU

## Что изменено

### 1. Численная устойчивость

`Tasks/Filter_task/filter_task.c`:

- Все шесть входных компонент и `dt` проверяются через `isfinite`.
- Кватернион нормируется только при конечном квадрате нормы не меньше
  `1e-12`. Нулевые и повреждённые кватернионы отвергаются.
- При квадрате нормы градиента `<= 1e-12` коррекция акселерометром
  пропускается; интегрирование гироскопа продолжается. Это исправляет NaN
  при `q=[1,0,0,0]`, `accel=[0,0,1]`.
- Новое состояние сначала считается во временном массиве и проверяется.
  Неудачный шаг исключает датчик из текущего результата.
- Первый пригодный сэмпл, возвращение после пропуска больше 10 мс или
  обнаружение повреждённого состояния вызывают переинициализацию:
  `roll=atan2(ay,az)`, `pitch=atan2(-ax,sqrt(ay²+az²))`.
  Yaw берётся из последнего достоверного общего результата, при старте — 0.
  Вращение во время отсутствия всех датчиков восстановить невозможно.
- Средний кватернион и итоговые углы проверяются перед признанием результата
  достоверным. Формулы преобразования кватерниона в углы не менялись.

### 2. Присутствие и готовность датчиков

- LSM6DS3TR-C: проверяется `WHO_AM_I=0x6A`. Для нового чтения нужны оба
  флага `XLDA/GDA` в `STATUS_REG=0x1E`.
- MPU6500: проверяется `WHO_AM_I=0x70`. Новый сэмпл читается при
  `DATA_RDY_INT` в `INT_STATUS=0x3A`. `INT_PIN_CFG=0` гарантирует, что
  чтение WHO_AM_I не сбрасывает этот флаг. Диапазоны явно заданы
  ±2g / ±250°/с для соответствия коэффициентам преобразования.
- ID проверяется при инициализации и при каждом опросе готовности.
- Ошибка SPI, неверный ID или отсутствие новых данных дольше 100 мс
  переводят датчик в offline. Его очередь помечается невалидной.
- Повторная инициализация offline-датчика выполняется не чаще раза в 1000 мс,
  без циклов ожидания. В исправной шине остальные датчики продолжают опрос.
  Существующие блокирующие HAL-таймауты сохранены: при неисправности самой
  SPI-шины частота 500 Гц не гарантируется.
- Инициализация и начальная задержка 100 мс перенесены в тело IMU-задачи,
  после запуска планировщика. До старта планировщика больше нет HAL_Delay
  после создания другой FreeRTOS-задачи.
- BMI270 явно не участвует в обработке: `Init` проверяет ID `0x24`, но
  возвращает false до реализации загрузки обязательной конфигурации.
  Проверка ID сама по себе не считается успешной инициализацией.

Отсутствие DRDY не равно ошибке: до истечения таймаута новый сэмпл не
публикуется, старая метка времени не обновляется. Одинаковые численные
значения при наличии DRDY допустимы — неподвижный датчик не бракуется
только из-за одинаковых показаний. Неисправность, имитирующая одновременно
правильные ID, DRDY и правдоподобные данные, этими проверками не выявляется.

Сохранена прежняя проверка модуля ускорения `(0.1g, 2.2g)`. Она ограничивает
применимость при свободном падении и больших ускорениях; это не универсальный
критерий исправности. Калибровка, преобразование осей и фильтрация шумов
в этой правке не добавлялись.

### 3. Новые сэмплы и время

- Очередь длины 1 хранит последнее измерение. Новая публикация происходит
  только после DRDY и успешного чтения; timestamp — HAL_GetTick после чтения,
  с разрешением 1 мс, не аппаратное время измерения.
- В фильтре сохранена последняя обработанная метка каждого датчика.
  Повтор той же метки не вызывает повторного шага Madgwick.
- Для нового измерения `dt=(timestamp_new-timestamp_previous)/1000`.
  Вычитание беззнаковое: переполнение 32-битного счётчика поддерживается.
- При интервале больше 10 мс фильтр переинициализируется, а не интегрирует
  единственное измерение за весь пропуск. При первом измерении интеграции нет.
- Последний результат датчика может участвовать в усреднении до возраста
  10 мс включительно, но повторно не интегрируется. После этого исключается.
- Это обработка последних доступных измерений, без FIFO и интерполяции:
  промежуточные сэмплы могут быть пропущены, синхронизация датчиков не добавлена.

## Общий результат и UART

В `FusionOutput_t` добавлены `valid` и `used_mask`:

| used_mask | Используемые датчики |
|---|---|
| 0x00 | Ни одного, valid=false |
| 0x02 | LSM6DS3TR-C |
| 0x04 | MPU6500 |
| 0x06 | LSM6DS3TR-C и MPU6500 |

Бит 0 зарезервирован под BMI270. `fault_mask` по-прежнему означает только
отбраковку голосованием, не отсутствие устройства. При двух датчиках прежнее
голосование большинством не работает; выбрать виновного при расхождении двух
по этим данным нельзя. Усреднение выполняется по числу реально включённых
датчиков, не по константе 3.

UART пропускает результат с `valid=false` или возрастом результата больше
10 мс. Формат пакета 52 байта сохранён; новые служебные поля доступны только
внутри прошивки/отладчике. При потере всех датчиков пакеты прекращаются,
после восстановления возобновляются. Хост должен распознавать отсутствие
пакетов по своему таймауту. Метка UART осталась временем подготовки отправки.

## Проверки

`python tests/run_safety_tests.py` запускает C-тесты через MSVC 2022 Community.
Тесты используют реальные функции фильтра (извлечённые без переписывания),
имитацию очереди и реальные драйверы с имитацией HAL SPI.

Проверяются: 10000 шагов при нулевом градиенте, NaN/Inf/переполнение норм,
нулевой и большой dt, преобразование известного наклона, повторная метка,
шаг yaw с известным dt, устаревание, возвращение датчика, восстановление NaN,
переполнение timestamp, неверные ID 0/0xFF, готовность/неготовность,
исчезновение ID во время работы, ошибка SPI и запрет неполного BMI270 Init.

На плате нужно проверить запуск с каждым из двух рабочих датчиков по
отдельности, исчезновение/возврат данных, `used_mask`, отсутствие NaN,
остановку UART при потере всех измерений и возобновление после возврата.
Электрические подключения меняют при снятом питании.
