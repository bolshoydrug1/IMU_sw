# Контекст проекта IMU_sw

Снимок на 2026-11-03. Это переносимая выжимка работы с пользователем,
не полный журнал переписки. Перед продолжением сверить с кодом и git diff.

## Текущий этап и следующий шаг

Пользователь хочет сервисную калибровку IMU с обратной связью для GUI.
Сначала обсуждался интерфейс, затем пользователь попросил подготовить
линкер. Линкер уже изменён; по последнему решению оставлен ОДИН сектор.

Далее планируется:

1. Реализовать быструю калибровку гироскопов с хранением результата в RAM,
   защитой от движения и пакетами состояния для сервисного GUI.
2. После её проверки — медленную совместную калибровку акселерометров и
   гироскопов с записью во Flash.

На момент этого снимка алгоритмов калибровки и Flash-драйвера в коде НЕТ.
Последняя задача — создать эти файлы контекста, а не начинать калибровку.

## Аппаратура, сборка и структура

- STM32F401RCT6: Flash 256 КиБ, RAM 64 КиБ, Cortex-M4F.
- STM32CubeMX, HAL STM32F4, FreeRTOS через CMSIS-RTOS v2; C11.
- Проект CMake `IMU_sw_1`, Ninja, GNU Arm Embedded; пресеты Debug/Release.
- ELF: `build/Debug/IMU_sw_1.elf`, `build/Release/IMU_sw_1.elf`.
- Активный GCC linker script: `STM32F401XX_FLASH.ld`.
  Другой файл `STM32F401RCTX_FLASH.ld` остался от прежнего проекта;
  не считать его активным без проверки toolchain.
- Отладка VS Code: Cortex-Debug, J-Link или ST-Link, SWD.
- Пользовательские исходники подключены в верхнем `CMakeLists.txt`.
  Генерируемая часть — `cmake/stm32cubemx/`.
- `My_drivers/` — драйверы; `Tasks/IMU_task/` — опрос;
  `Tasks/Filter_task/` — ориентация, объединение, температура;
  `Tasks/UART_task/` — команды и передача; `Protocol/` — бинарный протокол.

## Что реализовано

### Датчики и фильтр

- MPU6500 на SPI1, LSM6DS3TR-C на SPI2, BMI270 на SPI3.
- LSM проверяет ID 0x6A, MPU — 0x70; используются флаги готовности новых данных.
- BMI270 проверяет ID 0x24, но Init возвращает false: загрузка обязательной
  конфигурации не реализована. Он намеренно не участвует в объединении.
- Опрос и фильтр имеют период 2 мс. При ошибке SPI/ID датчик исключается.
  При отсутствии новых данных больше 100 мс переводится offline,
  повторная инициализация — не чаще раза в секунду.
- Фильтр исключает данные старше 10 мс. Одна временная метка не интегрируется
  дважды; dt рассчитывается по меткам новых измерений, с учётом переполнения.
- Madgwick защищён от нулевого градиента, нулевых норм, NaN/Inf.
  После пропуска больше 10 мс/повреждения состояния наклон переинициализируется
  по ускорению, yaw — по последнему общему результату (при старте 0).
- Усреднение выполняется по реально участвующим датчикам. При двух источниках
  голосованием нельзя определить виновного при расхождении.
- `FusionOutput_t` содержит `valid`, `used_mask`, `fault_mask`.
  Биты: BMI=0x01, LSM=0x02, MPU=0x04; обычно используются LSM+MPU=0x06.
- Формулы quaternion→Euler стандартные; yaw без магнитометра дрейфует.
  Приведение индивидуальных осей IMU к осям платы ещё требует проверки.
- Выходные accel/gyro — среднее измерений выбранных датчиков, а не отдельная
  фильтрация шумов. В accel сохранена гравитация.
- Сохранена проверка модуля accel `(0.1g, 2.2g)`; это ограничивает работу при
  свободном падении/сильном ускорении и не является универсальной диагностикой.

### Температура

- LSM читается единым блоком 14 байт с 0x20: temp, gyro, accel.
  Перевод `25 + raw/256` °C.
- MPU использует temp из существующего блока; `21 + raw/333.87` °C.
- Индивидуальные температуры передаются через IMU_Sample_t.
- Для телеметрии берётся среднее пригодных выбранных источников и БИХ:
  `filtered += alpha * (mean - filtered)`.
- Макрос `TASK_FILTER_TEMPERATURE_IIR_ALPHA=0.15f` в `filter_task.h`.
  Первое значение равно среднему; дубликаты сэмплов не дают повторного шага.
  Без источников состояние сбрасывается. Нет температуры — результат невалиден.
- Общая температура предназначена для телеметрии; для будущей индивидуальной
  термокомпенсации нужны собственные температуры IMU.

### UART и текущий протокол

- USART1, PA9 TX / PA10 RX, 1 000 000 бод, 8N1, без flow control.
- Период отправки не равен скорости линии. Поддерживаются:
  0x00=100 Гц, 0x01=250 Гц, 0x02=500 Гц, 0x04=по запросу.
  Код 0x03 (бывшие 1000 Гц) отклоняется. После перезапуска — 500 Гц.
- `MODE_CONFIG` 0x07, payload 1 байт. ACK/NACK 0x02 с payload `07 00`
  при успехе, `07 01` при ошибке. Режим сохраняется только в RAM.
- Пустой запрос TELEMETRY 0x01 вызывает один ответ в любом режиме.
- RESET 0x08 реализован с magic 0xDEADBEEF. TIME_SYNC 0x03 и старые
  CALIB_ACCEL 0x04 / CALIB_GYRO 0x05 пока возвращают NACK.
- ISR сохраняет байты и времена их прихода в кольцевой буфер. Задача
  разбирает RX каждые 2 мс независимо от частоты телеметрии.
- После команд используется новый режим: при переходе в ON_REQUEST нет
  лишнего пакета после ACK. При смене частоты отсчитывается полный новый период.
- `PROTOCOL_RX_FRAME_TIMEOUT_MS=20u`: таймаут между байтами по времени ISR,
  не по времени выполнения задачи. После ошибок CRC/длины есть ресинхронизация.
- Текущая версия протокола 3. Телеметрия: payload 49 байт, кадр 57 байт.
  Little-endian, float32, packed; размер C enum не используется на линии.

| Смещение в кадре | Поле |
|---|---|
| 0 | AA |
| 1 | тип 01 |
| 2 | версия 03 |
| 3–4 | длина payload 31 00 |
| 5–12 | timestamp_ms, uint64, время отправки с запуска |
| 13–24 | gyro XYZ, °/с |
| 25–36 | accel XYZ, g |
| 37–48 | roll/pitch/yaw, градусы |
| 49–52 | общая фильтрованная temperature_c |
| 53 | status: 0=OK, 1=ERROR |
| 54–55 | CRC16 CCITT-FALSE по байтам 1–53, LE |
| 56 | 55 |

При пустой очереди/невалидных/устаревших данных пакеты продолжаются с заданной
частотой: все 10 float-полей нулевые, статус ERROR, timestamp обновляется.
Enum статуса телеметрии отдельный: `Protocol_TelemetryStatus_t`;
`Protocol_Status_t` относится к ответам команд.

### Разметка Flash — последнее решение пользователя

| Область | Адреса включительно | Размер |
|---|---|---|
| Векторы, сектора 0–1 | 0x08000000–0x08007FFF | 32 КиБ |
| Калибровка, сектор 2 | 0x08008000–0x0800BFFF | 16 КиБ |
| Код/константы/инициализаторы RAM, сектора 3–5 | 0x0800C000–0x0803FFFF | 208 КиБ |

Только векторы находятся в нижней области; её остаток пока не используется.
Reset_Handler находится в основном коде и указан в векторах; VTOR не переносился.
Символы линкера: `__calib_flash_start__`, `__calib_flash_end__`
(исключающий), `__calib_flash_size__`. Двухсекторные символы удалены.
CMake LINK_DEPENDS следит за изменением скрипта.

Flash-драйвера нет. Будущая схема — журнал в одном секторе, CRC и признак
завершения последним. При заполнении сектор стирается целиком; резервной
копии в другом секторе не будет. Это сознательно выбранное пользователем
упрощение: сбой питания в этот момент может оставить устройство без калибровки.
Такое состояние нужно явно диагностировать, а не считать успешной калибровкой.

Прошивать адресным ELF/HEX. Сплошной BIN перекрывает промежуток с калибровкой.
Сохранность данных также зависит от режима стирания программатора; mass erase
их удаляет. Отладчик/программатор на сохранение реальных данных ещё не проверялся.

## Требования пользователя к будущей калибровке

- Допуск остаточного систематического смещения gyro: не больше 0.05 °/с
  по оси; accel: не больше 0.05 g. Шум в эти требования НЕ входит;
  отдельную фильтрацию шумов пользователь хочет обсуждать позже.
- Эталонной угловой скорости нет. Калибруем ноль gyro в покое,
  масштаб и межосевые ошибки гироскопа пока не определяем.
- Accel: одно фиксированное положение платы, Z ВВЕРХ,
  ожидаемый вектор [0,0,+1 g] в системе платы. Определяются смещения,
  но не масштабы. Малый наклон от bias однозначно неотделим.
- Нужна защита от неверного положения и движения на всём протяжении
  процедуры. При обнаруженном движении — ошибка, не автоматический перезапуск.
  Численные пороги движения/допустимого наклона ещё не выбраны по реальным данным.
- Быстрая: только gyro, максимум 10 секунд, результат только в RAM.
- Медленная: gyro+accel вместе, максимум 40 секунд суммарно, включая Flash.
- Температурная калибровка ОТЛОЖЕНА: нет условий для её проведения.
  Не обещать сохранение точности при произвольном изменении температуры.
- Отдельные коэффициенты каждого датчика; применять до Madgwick/усреднения.
  Собирать показания до применения старых коэффициентов, чтобы повторные
  процедуры заменяли калибровку, а не суммировали поправки.
- Новые коэффициенты проверять на независимом окне. При ошибке/отмене
  сохранять предыдущие. Быстрая не должна менять accel и постоянный комплект.
- GUI сервисного обслуживания должен получать этапы, прогресс и точную ошибку.

## Рабочий проект интерфейса калибровки — ЕЩЁ НЕ В КОДЕ

В обсуждении предложен следующий интерфейс. Пользователь согласился двигаться
дальше, но до реализации в первую очередь попросил изменить линкер. При
продолжении не путать этот проект с уже реализованным протоколом.

### Пакеты и структуры

- 0x09 CALIB_CONTROL: команды GUI и немедленный ответ.
- 0x0A CALIB_STATE: состояние и окончательный результат процедуры.
- 0x0B CALIB_RESULT: коэффициенты и остаточные ошибки одного IMU.
- Старые 0x04/0x05 оставить зарезервированными/NACK, не дублировать интерфейс.

Все поля на линии фиксированной ширины, packed, LE.

| Структура | Поля в порядке передачи | Payload |
|---|---|---|
| Control | request_id u32, operation_id u32, action u8, profile u8, sensor_mask u8, reserved u8 | 12 |
| ControlReply | request_id u32, operation_id u32, action u8, accepted u8, error_code u8, reserved u8 | 12 |
| State | operation_id u32, elapsed_ms u32, profile u8, stage u8, progress u8, required_mask u8, ready_mask u8, failed_mask u8, error_code u8, storage u8 | 16 |
| Result | operation_id u32, sensor_id u8, valid_fields u8, storage u8, reserved u8, gyro_bias_dps float[3], accel_bias_g float[3], gyro_residual_dps float[3], accel_residual_g float[3], temperature_c float | 60 |

Actions: START=1, CANCEL=2, GET_STATE=3, GET_RESULT=4.
Profiles: GYRO_QUICK=1, FULL_SLOW=2.
Stages: IDLE=0, CHECKING=1, COLLECTING=2, COMPUTING=3, VERIFYING=4,
SAVING=5, DONE=6, FAILED=7, CANCELLED=8.
Storage: не применено=0, RAM=1, Flash=2.
valid_fields: bit0 gyro, bit1 accel. Progress 0..100 относится к текущему этапу.

Ошибки 0x00..0x0D по порядку: NONE, BUSY, BAD_REQUEST, SENSOR_MISSING,
SENSOR_DATA_ERROR, WRONG_ORIENTATION, MOTION_DETECTED, NOT_ENOUGH_SAMPLES,
BIAS_OUT_OF_RANGE, VERIFICATION_FAILED, TIMEOUT, FLASH_ERROR,
OPERATION_NOT_FOUND, INVALID_STAGE.

### Поведение

- request_id назначает GUI; повтор START с тем же ID не перезапускает процедуру.
  Детали срока хранения/дедупликации request_id ещё нужно определить.
- operation_id назначает модуль; START передаёт 0. GET_STATE с 0 запрашивает
  текущую/последнюю операцию. Результаты выдаются отдельно на каждый датчик.
- Предложенный обязательный комплект — LSM+MPU (mask 0x06), без незаметного
  частичного успеха. BMI пока исключён.
- Немедленный accepted означает только принятие команды. DONE — успешное
  завершение; для медленной — после проверки записи Flash.
- State при смене этапа и раз в 200 мс, независимо от режима телеметрии.
  Последний итог доступен до следующего запуска/перезагрузки.
- CANCEL разрешён до SAVING; при записи отказ INVALID_STAGE.
- Предложенные интервалы: quick 2 с проверка + 5 с сбор + 2 с проверка
  результата, весь процесс <=10 с; slow 3+25+5 с плюс сохранение, всего <=40 с.
  Реализация должна учитывать общий дедлайн и нехватку новых сэмплов.
- Предложено добавить статус телеметрии CALIBRATING=2 с нулевыми float-полями.
  Сейчас такого enum/поведения ещё нет. Размер телеметрии менять не требуется.
- Старый проект хранения с A/B отменён: реализовывать ОДИН сектор, как выше.

## Сборка и проверки на другом устройстве

В PATH нужны CMake >=3.22, Ninja и arm-none-eabi GCC/G++/binutils.
Пресеты не должны зависеть от сохранённого CMakeCache с другого компьютера.

```powershell
cmake --preset Debug
cmake --build --preset Debug
cmake --preset Release
cmake --build --preset Release
python tests/run_safety_tests.py
python tests/check_flash_layout.py build/Debug/IMU_sw_1.elf build/Release/IMU_sw_1.elf
```

`run_safety_tests.py` сейчас ориентирован на Windows и MSVC 2022 Community
(путь к vcvars64.bat задан в скрипте); это не переносимый Linux-тест без доработки.
Он проверяет реальные функции C с моками, а не отдельную Python-копию алгоритма:
численную устойчивость, новые сэмплы, температуру/БИХ, драйверы, CRC/размеры,
ACK/NACK, 16 переходов UART-режимов, таймаут/ресинхронизацию и переполнение тиков.

`check_flash_layout.py` использует стандартную библиотеку Python, проверяет
секции и PT_LOAD ELF, таблицу векторов, Reset_Handler и linker-символы.

На исходном компьютере обычный Debug ранее сталкивался с ошибкой запуска
ST-компилятора `Illegal System DLL Relocation`. Проверочные Debug-сборки
делались в `build/Debug-validation` с отдельным установленным Arm GNU.
Это локальная диагностика окружения, не рекомендуемый перенос кэша.
Последние проверочный Debug и Release после перехода на один сектор собраны;
ELF-проверка прошла для обоих. Проверки на реальной плате агент не выполнял.

Не переносить абсолютные пути к компиляторам/SEGGER из чужих настроек без
проверки. Перенести исходники, .vscode, CMake, tests и docs через Git или копию
проекта; каталоги сборки создавать заново. В исходном checkout есть ранее
отслеженные файлы build: не удалять/откатывать их попутно без отдельной задачи.
Файлы контекста не создают коммит и не синхронизируются сами по себе.
